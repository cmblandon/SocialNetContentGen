## Scope note

No `.env` file exists in this project, so `ANTHROPIC_API_KEY`/`JINA_API_KEY`/
`FIRECRAWL_API_KEY` are all unset. The real `/research/run` route (with its
default, non-overridden dependencies) constructs real `JinaScraperAdapter`,
`FirecrawlScraperAdapter`, and `AnthropicLLMClient` instances that would make
genuine outbound calls to `r.jina.ai`, `api.firecrawl.dev`, and the Anthropic
API. Firing such calls from an automated verification step — against real
third-party services, without configured credentials, and with no control
over their live content — is not appropriate here. The full happy path
(discover → curate → write → adapt → persist, all four platform versions
ending up `pending_review`) is already verified in
`tests/unit/test_research_endpoint.py` via `TestClient` + `dependency_overrides`
injecting fakes for every external dependency — that is the correct place
for that coverage. This curl session verifies what's safely testable against
the real, live server: request validation and route wiring.

## Endpoint Tests

### POST /research/run — empty source_urls
- Command: `curl -s -i -X POST http://127.0.0.1:8125/research/run -H "Content-Type: application/json" -d '{"source_urls": []}'`
- Response: `422`, `{"detail":[{"type":"too_short",...,"msg":"List should have at least 1 item after validation, not 0",...}]}`
- Result: PASS — matches the `Field(min_length=1)` constraint

### POST /research/run — missing field
- Command: `curl -s -i -X POST http://127.0.0.1:8125/research/run -H "Content-Type: application/json" -d '{}'`
- Response: `422`, `{"detail":[{"type":"missing","loc":["body","source_urls"],"msg":"Field required",...}]}`
- Result: PASS

### POST /research/run — malformed JSON body
- Command: `curl -s -i -X POST http://127.0.0.1:8125/research/run -H "Content-Type: application/json" -d 'not json'`
- Response: `422`, `{"detail":[{"type":"json_invalid",...}]}`
- Result: PASS

### POST /research/run — wrong type
- Command: `curl -s -i -X POST http://127.0.0.1:8125/research/run -H "Content-Type: application/json" -d '{"source_urls": "not-a-list"}'`
- Response: `422`, `{"detail":[{"type":"list_type","msg":"Input should be a valid list",...}]}`
- Result: PASS

### GET /research/run — wrong method
- Command: `curl -s -i -X GET http://127.0.0.1:8125/research/run`
- Response: `405 Method Not Allowed`, `Allow: POST`
- Result: PASS — confirms the route is POST-only as intended

### POST /research/does-not-exist — no route collision
- Command: `curl -s -i -X POST http://127.0.0.1:8125/research/does-not-exist`
- Response: `404 Not Found`
- Result: PASS
