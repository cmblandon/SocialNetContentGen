# Step 3.3 Report - Manual Endpoint Testing with curl

- Date: 2026-09-05
- Change: enhance-admin-panel-ui
- Agent: Claude Code

## Test Environment
- Backend started: `uvicorn src.editorial.presentation.app:app --port 8123` (background)
- Health check: `curl -s http://localhost:8123/health` → `{"status":"ok"}`
- Seeded two `PENDING_REVIEW` platform versions directly against the real
  `data/knowledge_base/editorial.sqlite` via `persist_story` (the same
  helper the test suite uses), one to approve+publish, one to leave
  pending for the 409 case:
  - `PLATFORM_VERSION_ID=06b2d066-ac2d-412f-a08e-2efdd6d7ef81` (approved → published)
  - `PLATFORM_VERSION_ID=9b554bee-95e8-4bb8-93ba-fe94c128113b` (left pending, for the 409 case)

## Commands and Results

1. **Approve no longer publishes**
   - `curl -X POST http://localhost:8123/platform-versions/06b2d066.../approve`
   - → `200 {"id": "06b2d066...", "status": "approved"}` — no `publish_outcome` key, confirming the decoupling (task 1.4) holds against the live server, not just the test client.

2. **Publish — unknown id**
   - `curl -X POST http://localhost:8123/platform-versions/does-not-exist/publish`
   - → `404`

3. **Publish — approved version**
   - `curl -X POST http://localhost:8123/platform-versions/06b2d066.../publish`
   - → `200 {"published": false, "external_post_id": null, "error_message": null, "proposed_time": "12:00"}`
   - No `optimal_time` was configured for `tiktok` in `calendario.md` yet, so `PublishingUseCase` took its "propose a time and hold" branch rather than actually calling the publisher — this is the documented, correct behavior for a fresh environment (see `PublishingUseCase._propose_time`), not a bug. A `PROPOSED optimal_time:tiktok=12:00` line was appended to `calendario.md` as the "record" of this outcome (cleaned up afterward — see Cleanup below). Verifying the actual-publish-success branch would require a running Postiz instance at `postiz_base_url`, which is out of scope for this local manual-testing pass (no `.env` / API keys configured in this environment).
   - Calling `/publish` again on the same id returned `200` again (still `approved`, since the propose-and-hold branch never mutates `PlatformVersion.status`) — consistent with `run_if_approved`'s gate only checking `status == APPROVED`.

4. **Publish — not-yet-approved version → 409**
   - `curl -X POST http://localhost:8123/platform-versions/9b554bee.../publish`
   - → `409 {"detail": "PlatformVersion 9b554bee... is 'pending_review', not 'approved' — refusing to proceed."}`

5. **Source URLs — list (empty, no `fuentes.md` yet)**
   - `curl http://localhost:8123/research/sources` → `200 {"source_urls": []}`

6. **Source URLs — add**
   - `curl -X POST http://localhost:8123/research/sources -d '{"url": "https://www.aaro.mil/reports/2024.pdf"}'`
   - → `200 {"source_urls": ["https://www.aaro.mil/reports/2024.pdf"]}`

7. **Source URLs — add duplicate (no-op)**
   - Same request repeated → `200 {"source_urls": ["https://www.aaro.mil/reports/2024.pdf"]}` (still one entry, confirming dedup)

8. **Source URLs — list (reflects the add)**
   - `curl http://localhost:8123/research/sources` → `200 {"source_urls": ["https://www.aaro.mil/reports/2024.pdf"]}`

9. **Source URLs — delete**
   - `curl -X POST http://localhost:8123/research/sources/delete -d '{"url": "https://www.aaro.mil/reports/2024.pdf"}'`
   - → `200 {"source_urls": []}`

10. **Source URLs — list (back to empty)**
    - `curl http://localhost:8123/research/sources` → `200 {"source_urls": []}`
